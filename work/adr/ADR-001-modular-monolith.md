# ADR-001：采用 TypeScript 模块化单体

- 状态：已接受
- 日期：2026-08-23

## 背景

V1 同时包含高交互 Web、事务型 API、定时计时任务和 Agent 长任务。小团队需要清晰边界，但当前吞吐、团队规模和独立发布需求不足以承担微服务的网络、消息一致性和运维成本。

## 决策

采用 pnpm monorepo 与 TypeScript 模块化单体。部署为 `apps/web`、`apps/api`、`apps/worker` 三个进程，共享领域包、合约包和同一 PostgreSQL。模块通过领域服务接口协作，不建立内部 HTTP 边界；核心领域不依赖 Next.js、Fastify、Drizzle 或 Agent SDK。

## 后果

- 任务、专注、轨迹可在数据库事务内保持强一致。
- Web/API/Worker 可独立扩缩容，但随同一产品版本发布。
- 模块越界需由代码审查和依赖方向约束防止。
- 只有当模块需要独立团队、独立扩容或独立故障域时，才评估拆分服务。
