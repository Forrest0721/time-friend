# ADR-002：当前状态表加追加式审计事件

- 状态：已接受
- 日期：2026-08-23

## 背景

任务列表和活动计时需要低延迟读取；轨迹解释又要求历史变化可追溯。完整 Event Sourcing 会引入投影重建、事件演进和最终一致性成本。

## 决策

`items`、`focus_sessions` 等表保存当前状态；`task_events`、`focus_adjustments`、`progress_entries` 追加保存审计事实。状态变更与审计记录在同一事务提交。轨迹使用当前状态、审计表和专注分段生成不可变快照，但 V1 不通过事件重建所有业务表。

## 后果

- 常用读取保持简单，关键修改仍可解释和审计。
- 领域命令必须保证状态与事件原子写入。
- 审计表不是通用事件总线；未来若需历史重放，要先定义稳定事件版本和投影迁移方案。
